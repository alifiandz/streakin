# Server enforcement integration

`EntitlementStore.ts` implements authoritative, user-scoped SQLite transactions for routine limits, memberships, stage gates, workout authorization/snapshot completion, idempotency and monthly AI reservations. It is **not connected to the static Sites prototype**. Node 22.13+ with `node:sqlite` is required; check the eventual Webuzo Node plan first. Use a persistent private disk and backups, never a public asset directory. Multi-instance hosting must use a shared transactional database adapter instead of independent SQLite files.

A production API must obtain `userId` from a verified server session. Never accept it from a request body, a public `x-user-id` header or browser storage. Membership changes must come only from verified billing webhooks or authorized server administration; the sample store's server key must never reach the browser. There is intentionally no public “set Pro” endpoint in this service. The prototype's `/api/v3/test-tier` exists only in browser-local test mode and must not be mounted in production.

Connect routing/auth and database operations before enabling cloud features. Use same-origin, CSRF-checked mutations, secure HttpOnly sessions, request validation, rate limits and owner authorization on every operation. Sites deployments must retain Sites authentication rather than adding a second OAuth system. Jagoan/Webuzo will need its own verified session provider (Google setup is separately documented). Port the SQLite store to the selected production database if necessary. The old inactive Next API files are not this service.

AI reservation is disabled by default. Activation requires a real validated provider, private video storage, explicit upload consent, malware/type/size checks and **server-probed duration**, then a reservation before dispatch. The caller supplies verified metadata from the server probe, never the browser's duration value. Reservations and completed jobs count toward 1 Free / 5 total Pro analyses per Asia/Jakarta calendar month. Failed jobs release a reservation; retries use the same idempotency key. A worker must settle failed or timed-out jobs so they do not remain pending indefinitely. Previous-month allowance does not carry forward. Provider callbacks require verified server authorization. No fake analysis scores are implemented.

A workout grant snapshots the authorized session. Finishing an already-admitted workout does not recheck subscription tier; this avoids a paywall interrupting an active session. Store full checkpoint drafts server-side to support multi-device recovery; the prototype currently stores those locally. The integration must provide secure import of local training records with explicit consent and idempotent IDs, without copying local test tiers or quota overrides into production memberships.

Server tests run against a real SQLite database in memory and verify owner isolation, forged-tier rejection, Free routine limits, Pro limits, monthly rollover, failed-job release, service-disabled rejection, 30-second limits, grant snapshot validation and completion after downgrade. Passing them does not mean auth, billing, AI or cloud synchronization is deployed.
